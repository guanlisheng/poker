# 多屏同步：让每个终端取得最新赛事状态

在固定场地，主屏、吧台屏和其他区域的显示设备可能需要同时展示同一场比赛。

如果每块屏幕独立计时或独立维护赛事状态，就容易出现不一致。

## 统一的赛事状态

按照当前产品架构，管理端和终端围绕服务器上的赛事状态工作。终端需要取得最新状态，显示当前级别、盲注和剩余时间。

## 主动通知与状态刷新

当前产品设计结合主动通知与周期性状态检查：

- 状态发生变化时，相关终端可以收到更新通知。
- 终端取得最新状态后刷新显示。
- 如果一次通知没有到达，后续状态检查可以再次取得最新数据。

具体延迟取决于网络和当前版本的实现，不能将“实时”理解为任何网络环境下绝对零延迟。

## 哪些操作会影响显示？

包括但不限于：

- 开始、暂停和继续
- 上一级、下一级
- 当前级别时间调整
- 修改主题
- 调整奖励文案
- 开关筹码图例
- 调整语音设置

具体同步范围以当前产品实现为准。

## 网络中断时怎么办？

建议区分两件事：本地是否继续显示，以及网络恢复后是否取得正确的比赛状态。

断网期间，终端可能暂时无法取得新信息。恢复后应重新连接并校准显示。

正式部署前，应当实际测试：

1. 临时断开终端网络。
2. 在管理端或服务器侧改变测试赛事状态。
3. 恢复网络。
4. 确认终端能否取得最新状态。
5. 检查倒计时、级别和盲注是否一致。

## 为什么需要明确设备绑定？

每台终端都应当明确对应哪场赛事。这样才能减少工作人员在多个赛事之间切换时的误操作。
